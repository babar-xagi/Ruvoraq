# 🚀 Ruvoraq 0.2.0 — Middleware & Observability

Experiment 011 makes requests easier to trace and browser integrations easier to configure while preserving route-only `main.rs` and explicit startup in `settings.rs`.

## ✨ New capabilities

- **Request IDs:** validated incoming `x-request-id` values or generated UUID v4 IDs; the same identifier reaches handlers, response headers and tracing events.
- **Typed RequestId extractor:** read correlation information without manually parsing a header.
- **Structured tracing:** opt-in JSON logs with method, static route pattern, status and time to response headers; handler events inherit the request span.
- **Explicit CORS:** HTTP(S) origin allowlists, optional credentials, browser preflight support and exposed request IDs. Ordinary OPTIONS requests retain method errors.
- **Request timeouts:** opt-in positive durations, cancellation of pending handler futures and consistent HTTP 408 errors, preserving CORS/request ID headers.
- **Typed environment controls:** RUVORAQ_REQUEST_ID, RUVORAQ_REQUEST_LOG and RUVORAQ_REQUEST_TIMEOUT_MS.
- **Automation:** default/all-feature/MSRV CI, a middleware coverage gate and tag-triggered GitHub release-note publication.

## 🛠️ Install or upgrade

```bash
cargo install ruvoraq-cli --version 0.2.0 --locked --force
# Optional PostgreSQL CLI migration support:
cargo install ruvoraq-cli --version 0.2.0 --features postgres --locked --force
```

Existing applications must update their framework dependency deliberately:

```toml
[dependencies.ruvoraq]
version = "0.2.0"
# Preserve any sqlite/postgres features you already use.
```

Source-development projects should retain their local path and update a version constraint if present. Old 0.1.x apps are not rewritten by reinstalling the CLI.

## 🧭 Defaults and behavior

Request IDs are enabled by default. Request logging, CORS and timeouts remain opt-in. The comprehensive example enables logging, a two-second deadline and the local frontend origin http://localhost:3000. Bootstrap initializes logging only when enabled and preserves an existing tracing subscriber.

Timeouts stop waiting for response headers; they do not cover streaming bodies, undo committed side effects or forcibly stop blocking/spawned work. CORS controls browser access and does not replace authentication. Request IDs are correlation data, not trusted identity.

## 🧪 Verification

- The production middleware module has **100% measured line/function/region coverage**, enforced by a script and CI.
- Whole-workspace coverage is separately measured and reported in the testing guide; **this release does not claim 100% coverage of the entire framework or branch instrumentation**.
- **92 regular tests per feature configuration, 146 live checks and five real PostgreSQL tests pass.** Strict Clippy, Rust 1.85.0 checks and all packaged-crate builds also pass.
- Whole-workspace line coverage: **88.52%**, including the real PostgreSQL test corpus.
- Cases include ID boundaries/duplicates/concurrency, origin/port validation, preflights, credentials, ordinary OPTIONS, timeout cancellation, safe logs, tracing context and configuration errors.

All six packages use version 0.2.0. The release is experimental; authentication, background jobs, admin, ORM tooling and AI remain future work.
